## New

- Multi-display support — run multiple screens from a single hub, each with its own resolution, rotation, and set of screens. A kitchen portrait touchscreen and a landscape living-room TV can coexist without either squashing the other's layout
- Display-only install mode — set up additional Pis as thin clients that connect to the hub with no Node.js required. Just run `install.sh --display-only` and point it at your hub
- Display picker in the remote control — target commands (brightness, profiles, sleep/wake, next/prev) at a specific display or broadcast to all of them
- Per-display settings with inheritance — each display can override defaults like weather location, theme, or active profile, with explicit "Override / Reset to default" controls
- Per-display owned profiles — assign different screen-rotation profiles to different displays and switch them independently

## Improved

- Settings page reorganized into "Defaults" and "Per display" sections so shared and display-specific settings each have a clear home
- Display switcher pill in the editor toolbar lets you jump between displays; the canvas automatically adjusts to each display's resolution and rotation
- Unadopted displays appear in the editor with their self-reported resolution, ready to adopt with one click — no manual IP lookup needed
- Displays that lose their configured URL auto-recover after a 60-second countdown instead of staying stuck until power-cycled
- Stale unadopted displays are automatically cleaned up after 2 minutes of silence so powered-off Pis don't linger in the editor
- Editor shows each display's IP address and last-seen time so you can identify which physical device is which
- Meal-planner settings now sync across all module instances and the remote control page — change a setting once and it applies everywhere
- Upgrade pipeline hardened against tampering, and the plugin API proxy has stronger protections against server-side request forgery

## Fixed

- Fullscreen meal planner showing "Now — Breakfast" late in the evening when no meal is active
- Chore chart timezone handling causing tasks to shift to the wrong day
- Background rotation silently failing for displays using per-display screens
- Display-only installer exiting silently when generating a unique ID on some systems
- Existing screens preserved when adding your first additional display — your current layout stays on the main display instead of disappearing
- Older installs (v0.25.0) unable to upgrade past v0.26.0 due to a missing cleanup hook
