## New

- Inter-module event bus — modules can now react to each other's state in real time. Weather data, time-of-day transitions, and alerts flow between modules automatically
- Weather-aware greetings and affirmations — greeting and affirmation modules respond to current weather conditions with contextual messages like "Rainy day ahead" or mood-appropriate affirmations. Can be toggled off per module
- Per-day chore scheduling — a new "Schedule" rotation type lets you assign specific family members to specific days of the week for any chore, with a visual grid for managing assignments
- IP allowlist — restrict access to your hub by IP address with CIDR-based rules. Two independent modes: skip display authentication for trusted IPs, or block all access from untrusted IPs. Includes lockout protection and a pre-save warning if you'd lock yourself out
- Config validation CLI — run `npm run config:check` to scan your configuration for issues like unknown module types, broken profile references, or out-of-range settings
- Light and dark theme support — the editor and remote control now support light mode, dark mode, and system-auto, with independent theme choices for each surface

## Improved

- All API routes automatically retry on server errors and rate limits with exponential backoff — no per-route changes needed. Plugin proxy redirects and non-idempotent traffic calls are excluded
- Plugins can subscribe to the event bus to receive weather and time-of-day updates via the SDK
- Weather data is fetched whenever location is configured, even without a weather widget on screen, so weather-aware modules always have data to work with
- Warning shown in the editor when weather-aware features are enabled but no location is configured

## Fixed

- Chore points rejecting a value of 0 — entering 0 points silently defaulted to 1
- Chore history backdating letting already-spent points be silently erased — negative balances are now tracked
- "Snowstorm" misclassified as a thunderstorm in weather condition detection
- IP address shown as `::ffff:127.0.0.1` instead of `127.0.0.1` in the IP allowlist settings
- Login page redirect loop when an authenticated user's IP gets restricted
- Password changes silently dropping IP allowlist settings
